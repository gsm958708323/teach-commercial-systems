# 正式课程节交付契约

## 1. 正式课程节定义

正式课程节是计划确认后、围绕一个可验证学习目标展开的最小教学单元。需求访谈、方案选择、支线答疑和单纯进度汇报不是正式课程节，不强制生成代码。`00-course-outline` 是特殊课程设计节，可以只输出课程路线、范围和验收标准，不写代码。

一个正式课程节可以跨多轮对话，但不得与下一课程节混在同一回复中。

## 2. 开始前

1. 运行课程恢复命令并确认当前状态。
2. 运行上一节留下的 C# 基线验证；基线已通过且代码未变时不要重复运行。
3. 明确本节学习目标、最终项目增量和可运行证据。
4. 对会改变接口、数据流或模块边界的决策，先提供 3–5 个方案并等待选择。
5. 明确本节涉及的商业风险和学习验收方式；需要时读取 `commercial-readiness.md` 与 `learning-assessment.md`。
6. 在 `.course/plan.md` 细化当前节和下一节。

## 3. 教学顺序

严格按以下顺序推进：

```text
为什么需要本能力
  -> 替代方案和权衡
  -> 接口、数据结构、依赖图
  -> 最复杂需求调用链走查
  -> 项目内教学切片完整实现
  -> 运行 C# focused verification
  -> 主项目完整集成
  -> C# 针对性测试和必要回归测试
  -> 教学切片 / 主项目 / 商用候选版本边界说明
  -> 设计反推自检
  -> 逐节讲解归档
  -> checkpoint
  -> 等待用户确认
```

`00-course-outline` 课程设计节跳过代码实现、验证和主项目集成步骤，只生成课程路线文档、计划和 checkpoint。

## 4. 项目内教学切片

在主项目目录内创建最小教学切片，并满足：

- 使用与主项目一致的语言和主要运行时，除非本节明确解释差异。
- 只证明一个核心原理，保持依赖和文件数量最小。
- 包含完整入口、配置和运行命令，不依赖对话中的隐藏代码。
- 可以引用主项目源码；不要创建项目外独立 Demo 或第二套运行环境。
- 用可观察输出、自动化测试或交互场景证明原理，而不是只打印“success”。
- 在课程文档中写明预期输出和实际结果。

教学切片是教学实现。明确指出它省略了哪些商业项目能力，不把简化代码原样称为生产实现。

## 5. 主项目集成

在同一课程节完成主项目集成：

- 将教学切片中证明的概念映射到主项目所属模块。
- 遵循已有项目风格、模块边界和测试方式。
- 写完整实现，不用伪代码、`TODO` 或“其余省略”。
- 只增加当前课程节需要的抽象，不为假设中的未来需求建框架。
- 移除本节改动导致的未使用 import、变量和临时文件。
- 保持已有功能可运行，默认只运行 C# focused verification；Unity batchmode、完整 EditMode 或集成回归只在阶段边界、最终验收或用户明确要求时运行。
- 说明本节能力进入商用候选版本时，已解决、已隔离和留到后续的风险。

若只有 Demo 通过而主项目失败，将课程节标记为 `blocked`；不要以“原理已经证明”为由推进。

## 6. 讲解文档

从 `assets/templates/lesson.md` 创建 `docs/course/<course-id>/lessons/<lesson-id>.md`，至少包含：

1. 本节目标与为什么现在做。
2. 方案对比和用户选择。
3. 接口、数据结构和依赖方向。
4. 最复杂需求的调用链与状态流。
5. 项目内教学切片的文件、命令、预期和实际结果。
6. 主项目改动与代码走查。
7. 教学切片、主项目和商用候选版本的差异。
8. 本节核心设计原则、一个反例及其失败原因。
9. 常见错误和调试入口。
10. 已预留但本节不实现的扩展点。
11. 验证结果、设计反推自检场景和判断标准。
12. 下一节依赖。

讲解“为什么”时给出具体代价，不使用“这样更好”或“业界标准”作为完整理由。

## 7. 回复格式

回复以解释为主，完整代码保存在文件中：

- 最多展示 1–2 个关键代码片段。
- 使用文件链接指向完整实现和讲解。
- 汇报真实运行的 C# 验证命令和关键结果，不声称未运行的验证通过。
- 使用编号标题、表格和文本流程图；不使用 emoji。
- 文件路径、类名、接口名和命令使用反引号。

结尾必须包含小结、2–3 个自检场景、下一节预告，以及以下选项。至少一个自检场景必须要求用户判断新需求应该改哪里、不该改哪里和为什么。

1. 进入下一节。
2. 留在本节答疑。
3. 调整后续计划。

## 8. Definition of Done

只有全部满足时才能把课程节设为 `awaiting_confirmation`：

- 学习目标和设计理由已讲清。
- 重大决策已由用户选择并记录。
- 除 `00-course-outline` 外，项目内教学切片已完整生成。
- 主项目实现完整，并与教学切片的学习目标对应。
- C# focused verification 通过；必要回归测试按阶段或用户要求执行。
- 教学切片、主项目和商用候选版本的边界已说明。
- 本节直接相关的商业风险已解决、隔离或记录为后续工作。
- 至少提供一个设计反推题和判断标准，用于检查用户是否理解设计原理。
- 逐节讲解文档已生成。
- checkpoint 使用压缩摘要，并记录通过的 `csharp` 验证证据。
- 本节创建的主项目代码没有影响运行的占位内容。

验证失败时记录错误、当前假设和下一种不同尝试。连续三次不同尝试仍无法解决时，提供带权衡的求助选项并保持 `blocked`。
