# 商业验收轻量门槛

本文件定义“接近可商用”的最低本地验收。它不是上线清单；不要把课程变成部署、合规和运维大全。最终仍称为“本地完整、production-shaped 的教学项目”。

## 1. 三层产物边界

| 层级 | 目的 | 可以简化 | 不可混淆 |
|---|---|---|---|
| 项目内教学切片 | 证明一个设计原理 | 持久化、权限、监控、复杂错误 | 不称为生产实现 |
| 主项目集成 | 把能力接入最终系统 | 未承诺的上线设施 | 必须完整实现本节能力 |
| 商用候选版本 | 证明核心流程可交付 | 真实云环境和线上验证 | 必须说明剩余上线缺口 |

每节只检查与本节能力直接相关的商业风险。不要强制每节都覆盖所有维度。

## 2. 每节最小商业检查

正式课程节文档必须回答：

1. 本节能力支持哪个核心用户流程或系统能力。
2. 项目内教学切片省略了哪些商业能力，主项目补上了哪些。
3. 如果本节能力进入商用候选版本，最可能失败的边界是什么。
4. 本节哪些商业风险已解决，哪些明确留到后续阶段。

常见维度按需选择：

- 产品闭环：核心用户路径是否可走通。
- 数据与状态：状态迁移、幂等、一致性、恢复边界是否清楚。
- 权限与安全：谁能调用、谁能修改、输入如何校验。
- 可诊断性：失败时能否定位请求、状态、模块和关键参数。
- 质量：是否有针对性测试和必要回归。
- 性能边界：预期规模、热点和暂不优化的理由。
- 运行配置：启动、测试、环境变量和外部依赖是否明确。

## 3. 阶段 5/6 完整验收

系统集成和最终验收阶段必须建立或更新：

- 核心用户流程清单。
- 需求、代码、测试和课程节映射。
- 本地启动命令和完整测试命令的实际结果。
- 商业风险清单：已解决、已隔离、明确不包含。
- 未上线工作：真实部署、生产监控、告警、容量、故障演练等。

最终 checkpoint 的 `acceptance.commercial_readiness_checked` 必须为 `true`。

## 4. 反繁杂规则

- 不为假设中的未来规模加架构。
- 不因为“商业级”就默认上微服务、消息队列、缓存、权限系统或监控平台。
- 不在早期课程节实现完整部署体系。
- 对当前课程没有真实价值的检查，只记录为未包含上线工作。
